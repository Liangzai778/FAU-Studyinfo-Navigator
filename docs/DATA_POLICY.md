# FAU Study Navigator 数据政策

## 1. 原则

本项目采用本地优先、数据最小化、明确用途、用户可控和学术信息可追溯原则。应用不需要 FAU 登录，不采集 SSO 凭据，不建立云端用户档案，也不把个人学习记录发送给任何服务。

## 2. 数据分类

| 类别 | 示例 | 存储位置 | 默认保留 | 是否离开设备 |
|---|---|---|---|---|
| 公共参考数据 | 学院、官方入口、来源元数据、已核实 PO/规则/期限 | 构建内版本化 JSON | 随应用版本 | 否 |
| 个人学业数据 | 专业/PO 选择、课程状态、ECTS、学期计划、个人考试、报名自报状态 | IndexedDB | 直到用户清空 | 否 |
| 个人提醒与自定义项 | 学习任务、自定义链接、收藏 | IndexedDB/localStorage | 直到用户清空 | 否 |
| 低敏偏好 | 语言、主题、界面密度 | localStorage | 直到用户重置 | 否 |
| 临时数据 | 导入预览、表单草稿、筛选条件 | 内存 | 页面会话 | 否 |

不收集姓名、学号、FAU 密码、身份令牌、正式成绩单、浏览器指纹、精确位置、广告标识或跨站行为数据。用户可自行给课程起名，但产品应提示避免写入不必要的身份信息。

## 3. 个人数据处理规则

- 学习记录只用于本地展示、计划、ECTS 计算、备份和用户请求的 ICS 生成。
- 不使用 analytics、telemetry、远程错误上报、第三方聊天组件或云同步。
- 日志默认不包含课程名称、成绩、提醒正文或导入文件内容；开发错误只记录错误码和非敏上下文。
- 自定义 URL 必须校验协议；显示时转义，不允许 `javascript:`、`data:` 等可执行协议。
- 所有个人状态必须有清晰的查看、导出、更正和删除入口。

## 4. 公共学术数据政策

### 4.1 真实性与适用范围

- 不伪造课程、ECTS、考试要求、模块类别、日期或引文。
- 正式记录必须声明 `programmeId`、`poVersionId` 或明确的通用 scope，并绑定 Source。
- “最新”不等于“适用于当前学生”；不得自动将最新 PO 分配给用户。
- 无法确认时使用 `unverified/unknown`；预计信息用 `tentative`；来源冲突用 `conflict`。
- `lastCheckedAt` 只表示看过来源，不代表完成学术核验；只有人工核准才更新 `lastVerifiedAt`。

### 4.2 来源等级

优先顺序为：适用 Prüfungsordnung 及过渡条款 → 对应专业/学期的官方模块手册与 Campo → 官方学院/专业公告 → FAU 通用日期 → 社区经验。社区经验不得单独支撑正式 ECTS、考试或毕业结论。

### 4.3 本地更新流程

本项目不进行自动网页抓取、在线 API 同步或后台更新。维护者在应用之外人工查阅官方资料，再在当前项目目录中录入候选变更：

1. 记录来源 URL、发布者、文档类型、标题、版本、页码/章节和访问日期。
2. 明确适用 programme、PO、cohort、semester 与有效期。
3. 将变更先标为 `needs_review`，运行本地 schema 与一致性检查。
4. 按原文逐项人工复核；冲突不合并，保留双方证据。
5. 只有复核完成才改为 `verified` 并更新 `lastVerifiedAt`。

在线内容只作为人类主动访问的证据来源，不由产品运行时读取。用户主动点击官方外链会离开本应用，页面须提前说明。

## 5. 学分与考试数据规则

- earned ECTS 只来自 `passed` 和经用户确认的 `recognized`；planned、in_progress、failed、exam registration 都不增加 earned。
- recognized ECTS 必须有明确数值和确认状态；不能从计划值自动继承。
- 一门模块在互斥要求组只计算一次；重复尝试合并时保留历史但不重复计分。
- `examRegistration` 是用户本地自报字段，任何值都不能表达已从 Campo 验证。
- 个人考试日期固定标记为 `origin: personal` 与 `dateStatus: user_entered`，不得在界面或导出中提升为官方确认。
- 规则不完整、PO 不明确、来源冲突或 module version 歧义时，毕业判断为 `unknown`。

## 6. 日期与时区

- FAU 日期以 `Europe/Berlin` 语义存储和显示；保存原始 local date/time、时区、状态、scope、sourceIds 和核验时间。
- 不使用访问者系统时区静默改变官方日期。
- 全日事件不做 UTC 跨日换算；带时刻事件在导出时按 IANA 时区规则处理。
- 截止日期不会因为临近或已过去而自动改变 `tentative/confirmed` 的证据状态。

## 7. 导出、导入与删除

### 导出

- 完全在浏览器本地生成 JSON；不上传到服务器。
- 包含 schemaVersion、应用版本、导出时间和所选数据类别。
- 导出前提示文件可能含敏感学业信息，由用户自行保管。

### 导入

- 文件视为不可信输入，限制大小、条目数量、字符串长度、URL 协议和嵌套深度。
- 必须通过 JSON 解析、Zod schema、版本兼容、条目上限和内部强引用检查；已删除课程留下的考试/任务软链接允许保留并显示为缺失关联，不因此丢弃个人记录。
- 显示导入摘要并由用户确认；写入采用单事务，失败则保持原数据不变。
- 禁止解释 HTML、执行脚本、解析公式或从导入文件自动访问 URL。

### 删除

- “彻底清空”覆盖本应用的 IndexedDB、localStorage 命名空间、缓存中的个人数据和内存状态。
- 使用明确的二次确认，并说明不可恢复；完成后重新读取存储验证为空。
- 删除不影响随应用发布的公共只读数据。

## 8. 安全与隐私控制

- 依赖和静态资产必须本地打包；不使用第三方 CDN 或远程字体。
- CSP 限制连接、脚本、对象和表单目标；不使用内联可执行用户内容。
- 外链域名和协议经过 allowlist/验证并明确标记，不在 URL 中附加个人状态。
- 不在代码、备份或构建产物中包含密钥；项目正常运行不需要密钥。
- Service Worker 若未来启用，只缓存本地静态资产，不能后台同步个人数据或远程来源。

## 9. 用户权利与产品说明

用户可以在应用内查看、更正、导出和清空其本地数据。卸载浏览器、清除站点数据或更换设备可能永久丢失记录，因此应主动提供本地备份提示，但不制造云同步已存在的印象。

所有涉及考试、毕业和法律效力的页面都应说明：本工具仅提供导航和辅助校验；FAU 官方文件及 Campo 为准。来源过期、冲突或未核实时，应优先提示核对，而不是给出确定结论。

## 10. 禁止事项

- 连接云数据库、在线 API、分析平台或远程日志服务。
- 自动采集 FAU 页面、绕过 robots/认证、抓取 Campo/StudOn 登录内容。
- 请求、存储或转发 FAU 密码、session cookie 或 token。
- 以 schema 校验、AI 生成或社区说法代替人工学术核验。
- 将个人数据嵌入外链、二维码、错误报告或公开构建产物。
- 未经明确的新政策评审引入账号、云同步、通知推送或远程数据更新。
