# Code of conduct

This is a small student project with an unusually strict rule about data
honesty. The behaviour rules below exist so that correcting each other stays
possible.

## Expected behaviour

- Be direct about problems in the work, and civil about the person who did it.
- Assume the other person read a document you did not. Ask which one before
  concluding they were careless.
- When you say a number is wrong, say where the correct number comes from.
  "I think it is 5 ECTS" is not a correction; a page number is.
- Accept "I could not verify that" as an answer. It is the honest one.
- Write in the language you are comfortable with. Chinese, English and German
  are all fine in issues and pull requests.

## Not acceptable

- Harassment, insults, or personal attacks of any kind.
- Publishing someone's private data (student records, grades, email addresses,
  screenshots with a name in them).
- Pressuring anyone to upload FAU credentials, session cookies or login data.
  The project never needs them.
- Fabricating academic data on purpose, or removing an honest
  `needs_review`/`null` because it looks untidy.
- Spam, advertising, or unrelated self-promotion.

## Scope

This applies to issues, pull requests, discussions, commit messages and any
other project space. It also applies when you represent the project elsewhere.

## Reporting

If something happens, open an issue asking for a private channel, or contact the
maintainer through GitHub. Reports are read by the maintainer. Do not open a
public issue containing personal data.

## Consequences

The maintainer may edit or delete comments, close threads, reject
contributions, or block accounts. For a first, minor incident the response will
usually be a request to stop. Deliberate data fabrication is a hard block: it is
the one thing that can make a student plan a semester around a number that does
not exist.
